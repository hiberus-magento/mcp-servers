# @hiberus-magento/magento-graphql

An MCP (Model Context Protocol) server, and a companion operator CLI, for the
**Magento 2 / Adobe Commerce GraphQL API** of one instance — every Query and Mutation of
the core storefront schema: catalog, CMS, store, cart, checkout, customer account, wish lists, returns,
payments and the Adobe Commerce B2B operations — with every mutation switched off unless you turn them on.

> **This is not the REST server, and not EDS, ACS or ACO.** Adjacent names that are
> routinely confused:
>
> - **`magento-graphql`** — the GraphQL endpoint (`/graphql`) a headless or PWA storefront
>   uses: what a *shopper* can see. **This package.**
> - [`@hiberus-magento/magento-rest`](https://npmjs.com/package/@hiberus-magento/magento-rest) —
>   the admin/integration REST API of the same instance: orders, customers, stock, writes, SQL.
>   Use it for back-office questions; use this one for "what does the storefront see".
> - [`@hiberus-magento/magento-cloud`](https://npmjs.com/package/@hiberus-magento/magento-cloud) —
>   wraps the `magento-cloud` CLI for Cloud projects, environments and database.
> - **EDS** — Edge Delivery Services, served by
>   [`@hiberus-magento/eds`](https://npmjs.com/package/@hiberus-magento/eds).
> - **ACS** — Adobe Commerce Storefront: a commerce storefront built on EDS.
> - **ACO** — Adobe Commerce Optimizer, served by
>   [`@hiberus-magento/aco`](https://npmjs.com/package/@hiberus-magento/aco).

Single bundled file, zero runtime dependencies, so `npx` runs it with nothing
installed first.

Two kinds of tool: **curated** ones with a fixed query document and a bounded result,
and one **generic** `magentographql_query` for everything else, which runs exactly one
read-only query and refuses mutations before anything is sent.

## The two binaries

| Binary | What it is |
| --- | --- |
| `hiberus-magento-graphql-mcp` | The **stdio MCP server**. This is what you put in an MCP client's configuration. It speaks JSON-RPC on stdout and nothing else. |
| `hiberus-magento-graphql` | The **operator CLI**, for a human at a terminal. It stores the optional customer token (`auth token set`, from stdin) and checks the setup (`auth status`). It has no command that reads or writes store data. |

With two binaries declared, `npx` has to be told which one to run
(`npx -y --package @hiberus-magento/magento-graphql hiberus-magento-graphql-mcp`); the
bare `npx -y @hiberus-magento/magento-graphql` form exits with `could not determine
executable to run`.

## Tools

- `magentographql_search_products` (read-only) — Use this to search the storefront catalog by text, SKU list, category uid or price range, with sorting and paging: SKU, name, URL key, stock status, price range and thumbnail. It sees only what a shopper sees — disabled or not-visible products are absent.
- `magentographql_get_product` (read-only) — Use this to read one product as the storefront shows it, by SKU or URL key: descriptions, meta tags, stock status, price range, categories, gallery, and for a configurable product its options and variants.
- `magentographql_get_product_review_ratings_metadata` (read-only) — Use this to return the active ratings attributes and the values each rating can have. **Not verified against a live service** — this tool has not been run against a real Magento instance; its query document and response handling are covered by unit tests against a test double and by the conformance suite.

## Environment

- `MAGENTO_GRAPHQL_BASE_URL` (required) — The Magento GraphQL endpoint every magentographql_* tool addresses, e.g. https://<host>/graphql. Resolved on the first tool call and refused without it; tools/list still works. Must be https — plain http is accepted only for localhost.
- `MAGENTO_GRAPHQL_TOKEN` (optional) — A Magento CUSTOMER token, sent as a Bearer. Optional: the storefront schema is public, so every tool except the customer group works without one. It may come from this variable OR from the credential file written by `hiberus-magento-graphql auth token set`. Obtain it outside this server (the generateCustomerToken mutation): the server never mints or handles passwords.
- `MAGENTO_GRAPHQL_STORE` (optional) — The store view code sent as the `Store` header, e.g. `default`, so every tool reads that view. A tool's own `store` argument overrides it. Unset, Magento answers for the default view. Must be 1-32 characters of a-z, 0-9 and underscore.
- `MAGENTO_GRAPHQL_ALLOW_WRITES` (optional) — Set to exactly `true` to register every mutation tool (cart, checkout, account, wish list, returns, B2B and the rest; about 160 of them). Unset, or any other value, and the server registers read tools only — a mutation tool is then absent from tools/list, not merely refused. Read once at startup. The generic query tool never runs mutations, with or without this switch.
- `MAGENTO_GRAPHQL_GROUPS` (optional) — Comma-separated tool groups to load, e.g. `products,cms`, so a project registers only the tools it needs. Groups: `products`, `categories`, `cms`, `store`, `customer`, `account`, `cart`, `checkout`, `orders`, `returns`, `wishlist`, `compare`, `payments`, `gift-and-rewards`, `gift-registry`, `company`, `purchase-orders`, `quotes`, `requisition-lists`, `query`. Case-insensitive; blanks and repeats are ignored. Unset or empty loads every group. A name that is not a group stops the server with exit code 1, listing the valid ones. MAGENTO_GRAPHQL_ALLOW_WRITES still decides whether the mutation tools of a loaded group are registered. Read once at startup.

## Credentials

**None are needed** for the storefront schema: products, categories, CMS, store and cart
reads work anonymously. The tools in the `customer` group need a **customer token**,
sent as a Bearer. It comes from `MAGENTO_GRAPHQL_TOKEN`, or from
`$XDG_CONFIG_HOME/hiberus/magento-graphql.json` at file mode `0600`:

```sh
echo "$CUSTOMER_TOKEN" | npx -y --package @hiberus-magento/magento-graphql hiberus-magento-graphql auth token set
```

The server never mints a token and never sees a password: get one outside it (the
`generateCustomerToken` mutation). There is no `--token` flag — it is absent, not
rejected — so a token cannot reach shell history. A stored file with group or world
permissions is **refused, not treated as "no token"**: silently falling back to anonymous
would make you think the customer tools were authenticated. The token is read on every
call, so adding or replacing one takes effect without a restart. A customer token
expires (one hour by default in Magento); when it does, the customer tools say so and how to replace it.

## Read-only by default

With `MAGENTO_GRAPHQL_ALLOW_WRITES` unset, or set to anything but the exact string
`true`, the server registers **query tools only**: every mutation is absent from
`tools/list`, not merely refused when called. The choice is made once at startup.
Queries that hit a `429` or `5xx` are retried with backoff; a mutation is sent exactly
once, because replaying `addProductsToCart` after an ambiguous failure would add the item twice.
`magentographql_query` never runs a mutation, with or without the switch.

```json
"MAGENTO_GRAPHQL_GROUPS": "products,cms"
```

name that is not a group stops the server at startup with exit code 1 and the list of valid
groups. It is read once at startup, like the write switch, and the two are independent: a
group loads its read tools always, and its mutation tools (marked `*`) only with

## What this server deliberately does not do

- **No admin data.** GraphQL here is the storefront schema: no orders of other customers, no
  stock per source, no disabled products, no customers' list. That is `magento-rest`.
- **No mutation without the switch.** About 160 mutations exist, including `place_order` and the account tools that
  take a password or hand a token back; all of them are absent from the tool list unless
  `MAGENTO_GRAPHQL_ALLOW_WRITES=true`, and each is sent once and never retried. Use a test store and a test shopper.
- **No deprecated operations.** Magento hides them from introspection by default, and they are not generated
  (`categoryList`, `urlResolver`, `createEmptyCart`, `wishlist`, `customerOrders` and the like), and no tool selects a
  deprecated field. Use `magentographql_query` for any of them.
- **No mutation through the generic tool.** A small tokenizer reads the document first and
  refuses anything that is not exactly one query — comments, strings and fragments do not
  hide a mutation. Documents over 8,000 characters or nested deeper than 12 selections are refused.
- **No interpolation.** Every curated tool sends a fixed document and passes your arguments
  only as GraphQL variables, so a SKU or a search term cannot change the query.
- **No way to turn TLS verification off.** For a private certificate authority, make Node
  trust it with `NODE_EXTRA_CA_CERTS`.
- **No plain `http`** except for `localhost`: a Bearer over plain http is a Bearer on the wire.
- **No redirects.** A redirect would re-send the request, and the token, somewhere you never configured.
- **No raw errors.** GraphQL answers HTTP 200 with an `errors` array; only Magento's message
  survives, redacted and capped — never `extensions`, locations or a proxy's HTML.
- **No street, phone, birth date or tax id** in the customer tools, and no email or address in carts.
