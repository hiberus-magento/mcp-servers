Catalog writes (create/update product, update product attribute, add/update product media, create/update category) now run in the `all` store scope by default, so they change the global values instead of only the default store view's; pass `store_code` to change one store view. `create_product` takes `website_ids`; without it the product goes to the default website only (the `store_code` store view's website, or the only website; with several websites it asks for `website_ids`). CMS creates and updates always run in `all`, so a new block or page is on all store views (a page update keeps its assignment; a block update resets it, as Magento does on every REST block update). Revenue, product-sales and revenue-by-country leave out canceled and closed orders when no status is given, and never add amounts in different currencies together (they return `by_currency` instead). A REST tool call the MCP client cancels aborts its in-flight request (the database tools still run until their statement time limit).
